# 简章：从 Pwn 手到云原生，我的 eBPF 逆旅

本学习计划开启于 `2026.5.22`。

作为一名大三的学生，在折腾了两个多月的暑期实习投递，各种笔试、测评和面试之后，我已经没什么精气神了。更可怕的是某天晚上睡前发现，这段时间自己一直在看八股和复习以前的项目。没错，博主还没有过实习，所以在各种面试的时候只能把项目拉出来讲，这简直太可怕了。

但是，也感谢这段类似于（？）答辩的经历，让我在和技术官的交流中慢慢摸清了以后的方向。我大学前两年主要学的是冷门的二进制安全，或者简单来说，是个 `pwn` 手。玩过堆溢出、搞过 ROP，习惯了在汇编和内存里打转。但我越来越意识到，安全并非一根直线，它是一个圈，如今最激烈的战场已经从单体主机转移到了云原生环境。所以，我想往 `云原生安全` 的方向靠拢，之前也自学过一段时间的 Docker 编排，做了一个微服务聊天系统的安全加固。

可是，只会写 Dockerfile 和做基础加固，对于我这个有底层情结的人来说总觉得差点意思。直到我盯上了 **eBPF**——这个被称为“Linux 内核的黑魔法”的技术。它能让我用熟悉的 C 语言和内核数据结构，在内核态动态插桩，这简直是二进制选手进军云原生的完美武器！

于是，我拍脑袋做了一个疯狂的决定：**我的毕业设计就做《基于 eBPF 的容器运行时逃逸检测与防护系统》！**

说实话，这个决定让我既兴奋又焦虑。兴奋在于，eBPF + 容器安全绝对是云原生安全的核心竞争力，国内本科生能玩转这个的实在不多，这绝对是简历上最亮眼的仔；焦虑在于，这是一块实打实的硬骨头——eBPF 学习曲线极其陡峭，Linux 内核调试复杂，而且……我没有导师指导，没有实验室资源，暑假还要去实习。

但我就是想死磕一下。我给自己定了一个 **“生死线”**：在 6 月 22 日之前，如果我能独立写出 BCC 程序，跑通容器感知监控，我就继续死磕 eBPF；如果连 BCC API 都搞不定，我果断战术回退，老老实实去做纯 Docker 的容器逃逸检测。

所以，本系列的文章诞生了。这不会是一篇篇岁月静好的教程，而是一个网安本科生的 **“毕设生存日志”**。我会记录我如何从零死磕 eBPF，如何用内核级探针去捕捉容器逃逸的蛛丝马迹（比如 procfs 挂载、runc 漏洞、ptrace 滥用），如何踩坑 Verifier 报错，以及如何在实习和毕设的双重压力下保住头发。

我的主要学习资源来自《Learning eBPF》的中文翻译项目：https://binw666.github.io/learning-ebpf-translation/ ，同时会大量参考 Falco 和 Tracee 的源码。

如果你也对 eBPF 感兴趣，如果你也在从传统安全向云原生转型，或者单纯想看一个 pwn 手怎么在内核里翻车（和逆袭），欢迎和博主一起学习，也欢迎随时交流。毕竟，在这条又长又陡的道上，有人同行总归不孤单。

**Fight! 🚀**
