# Two、云原生下的 eBPF

date: 2026.5.22 - 2026.5.23

上一篇中，我们简单的了解了一下 eBPF 是什么，以及它怎么在内核中发挥作用的。

先点明一个核心事实：**云原生技术的基石是容器，而所有容器的底层都共享宿主机的 Linux 内核。**

这就意味着，谁掌握了内核层的观测和控制权，谁就拥有了对整个云原生集群的“上帝视角”。eBPF 正是那个帮你打开上帝视角的钥匙。

我们拿 eBPF 和几类经典的云原生组件/平台做个对比，就能明白它的降维打击在哪里了：

## 1. 网络管理：eBPF (Cilium) vs 传统 Service Mesh (Istio/Envoy)

- 传统 Service Mesh (Sidecar 模式)：
  - **原理**：在每个 Pod 里硬塞一个 Envoy 代理（Sidecar），拦截业务容器的所有进出流量。
  - **痛点**：**延迟高、资源开销大**。每个包都要从业务容器 -> 内核 -> Sidecar -> 内核 -> 网卡，走两次协议栈；而且每个节点都要跑几十个 Sidecar，吃内存。
- eBPF 方案 (如 Cilium)：
  - **原理**：在内核的网卡驱动层（XDP）或协议栈底层（TC）挂载 eBPF 程序，直接在内核里做路由、防火墙、负载均衡。
  - **优势**：**绕过协议栈，直通快车**。数据包根本不用走到用户态的代理，在内核层就被处理转发了。延迟极低，且不需要侵入业务 Pod。
  - **结论**：eBPF 是用**内核级的硬速**挑战 Sidecar 的笨重，目前业界的趋势是 Mesh 逐渐下沉到 eBPF（如 Cilium 的 Kernel Native Mesh）。

## 2. 可观测性：eBPF vs 传统监控 (Prometheus/Datadog Agent)

- 传统监控：
  - **原理**：依赖应用程序埋点（暴露 `/metrics` 接口），或者在用户态定期读取 `/proc`、`/sys` 目录下的文件。
  - **痛点**：**后知后觉、依赖应用配合**。如果是没埋点的老旧代码，你就监控不到；而且读 `/proc` 有延迟，高并发下性能差。
- eBPF 方案 (如 Pixie, Hubble)：
  - **原理**：在内核的 TCP 连接、系统调用等关键点插桩，实时捕获数据。
  - **优势**：**零侵入、全息透视**。不管你的代码是 Java、Go 还是 Python，不用改一行代码，eBPF 在内核层就能自动绘制出服务调用拓扑、捕获延迟指标。
  - **结论**：传统监控是“应用主动告诉你”，eBPF 是“我在内核偷听你”。

## 3. 安全防护：eBPF vs 传统 HIDS/Agent (Falco 旧版/常规安全工具)

- 传统安全 Agent：
  - **原理**：在用户态运行一个守护进程，周期性地扫描文件特征，或者通过 `auditd` 等机制读取系统日志。
  - 痛点：
    1. **盲区大**：很难把内核底层的异常事件（如 `ptrace` 附加）和具体的“容器身份”关联起来，只知道宿主机 PID，不知道是哪个容器干的。
    2. **资源消耗大**：高频扫描吃 CPU 和 IO。
    3. **可被绕过**：Pwn 手最喜欢干的事就是删日志、杀 Agent 进程（如果提权成功）。
- eBPF 方案 (如 Tetragon)：
  - **原理**：在内核的威胁路径上直接设卡（如 `execve`, `mount`, `ptrace`, `connect`），事件发生时瞬间捕获，并通过 Cgroup 信息自动打上“容器标签”。
  - 优势：
    1. **内核级溯源**：攻击者在用户态删日志没用，因为 eBPF 在内核层已经把事件通过 Ring Buffer 发出去了，杀 Agent 也来不及。
    2. **原生容器感知**：eBPF 天然能拿到 `task_struct` 里的 Cgroup ID，无需查表，一秒识别这是哪个容器在搞事。
    3. **可实时阻断**：这是杀手锏。eBPF 可以修改返回值，比如检测到敏感 `mount` 操作，直接返回 `-EPERM`（拒绝），把攻击扼杀在内核态，连用户态都走不到。
  - **结论**：传统安全是“查监控录像抓贼”，eBPF 安全是“在银行金库门口站了个带自动锁门功能的保安”。

## 综上

在云原生时代：

- **Kubernetes** 是大脑，负责调度（“把容器放这”）。
- **容器运行时** 是执行者，负责隔离（“用 Namespace 关住它”）。
- **eBPF** 是那个在内核里“看门 + 巡逻”的**锦衣卫**。它不归某个容器管，它直接听命于内核，看管着所有容器的底层行为。

当容器发生逃逸（比如利用 `CVE-2019-5736` 覆写 `runc`，或者 `procfs` 挂载逃逸），**所有的隔离（Namespace/Cgroups）都失效了，攻击者接触到了宿主机内核**。这时候，用户态的 Agent 已经不可信了，只有同样在内核态、且比攻击者更早启动的 eBPF 程序，才能干净、纯粹地捕捉到逃逸那一瞬间的异常系统调用，并具备实施“就地正法”（返回错误码阻断）的能力。

可以说，**eBPF 是目前对抗容器逃逸最天然、最锋利的武器**。
